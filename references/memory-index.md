# 跨期记忆索引（归档 / 重建 / 迁移时读）

> 本文件由 SKILL.md 按需加载：启动比对期号（本文件只需第 7 节）、会话压缩后、归档沉淀、建索引、重建索引、迁移旧快照时读。其余访谈时间不读。

## 0. 一句话：索引是后台弹药，不是用户看板

`记忆索引.md` 的唯一用途，是让采访者在第 2 次、第 5 次、第 10 次访谈时，仍然接得住用户说过的话、记得住没问完的钩子。

它不是给用户看的人生仪表盘，不是项目周报，也不是对人的定义。**索引里的系统词（主线卡 / 散点 / 休眠 / GC / 索引）永远不出现在对话和报告里。** 用户问"你记得我什么"时，用具体的、带语境的内容回答——"十月中那周你说，短视频像一本每天要清的账……"，不说"你的主线卡上写着……"。

## 1. 何时启用 / 关闭 / 回退

- **启用**：首期归档即创建，此后每期归档更新（create-or-update）。首期归档时全部材料都在上下文里，创建是零额外读取；一次性用户只会多一个可删的小缓存文件，不会多出访谈动作。
- **关闭**：用户说"别维护索引 / 这轮别落盘" → 本期归档时跳过索引写入（快照照常归档），一句"想恢复随时说"，不问原因、不解释机制，**不往文件里写任何"已关闭"标记**。以后启动看到「最后更新」落后、主题总表缺行，**只提示、不自动补写**（补写是归档动作，见第 7 节）。所以关闭是可执行也能撤销的：用户说恢复，下一次归档自然补齐并刷新「最后更新」。
- **回退**：没有索引时，走 SKILL.md 的旧轻读（grep 每份 `archive/*-progress.md` 的「反复浮现的词」+ 每份 report 的「人生主题/画像」）。有索引时轻读 = `记忆索引.md` 一份 + 最近一份 report 的「人生主题」「当前人物画像」两块（**当前区 `report.md`，无则取 `archive/` 内最新的 `*-report.md`**；索引里不存画像）。
- **已有 archive 但无索引**：启动时最多提议一次——"你这有 N 期快照。我可以把它们看一遍，把之前聊过的几条线记住，以后每次只补新的；要现在做，还是改天单开一次？" 不说"索引/沉淀"等系统词；回溯不在本次访谈里做。用户不要就继续旧轻读，本轮起不再提；下次他主动问起再答。

## 2. 三层架构与文件分工

```
第一层：原文层（事实源；AI 不改，用户可改）
  archive/*-progress.md / *-report.md / *-question-log.md
  archive/*-沉淀.html（二次合成纪要；回溯/定位用，不作一手引语来源）
  当前会话：progress.md / question-log.md / report.md
        ↓ 归档时提炼（单向）
第二层：记忆索引（派生缓存，常驻）
  记忆索引.md（六区：主线卡 / 反复浮现的词 / 主题总表 / 散点 / 背景区 / 档案）
        ↓ 休眠时封存（单向）
第三层：记忆归档（非驻，复活时只读取、不搬走）
  记忆归档.md（休眠主线全文卡 + 深归档全文卡）
```

**单向派生。** 原文 → 索引 → 记忆归档，永远不反向覆盖。索引坏了、删了，可以从 `archive/` 重建——但重建是"重新生成"，会丢失用户手改和原有合成措辞；重建前必须把旧索引备份为 `记忆索引.bak-YYYYMMDD.md`。

**`记忆归档.md` 的结构（新建时照此写、启动时按此读）：**

```markdown
# 记忆归档

> 非驻文件：休眠主线全文卡 + 深归档全文卡。组装时不读；复活时只读该线最近一张冷卡，读后不搬走。

### <线名>（休眠于 <期号>）
- 当前态：<休眠时的一句话>
- 时间线：**照搬索引里那张卡（≤8 行），不删行、不合并**
- 未决：≤5 条
- 休眠原因：连续 4 期无更新（活跃→常温→静默） / 12 个月未更新
```

复活时在卡标题下追加一行 `（已于 <期号> 复活；以下为复活前快照，当前态以主线卡为准）`——卡本身不删、内容不改。

**期 = 一个自然周。** 期号 = 快照所在周的 `YYYY-Wnn`（ISO 周，周一为一周之始）。同一周的所有快照（续传、`-Part2`、同一周多次独立访谈）合并为同一期，主题总表只占一行；不同周各自成期。「最近 / 排序」按该周周一的日期，不按字符串排期号。**没有事件式期号，也没有 `YYYY-MM` 期号。**

## 3. 记忆索引.md 六区结构

> 下面是**结构与行格式示例**（**全部虚构**）：只学区名、字段名、行格式与缩进；**内容一律不许照抄**——首期按本次材料重写。**任何示例都不得从真实用户的索引、报告或日记里复制。**

```markdown
# 记忆索引

> 派生缓存，不是事实源。事实源是 archive/ 快照。可从快照重建；重建会丢失用户手改，重建前先备份。
> 后台文件：本文件的系统词不进对话和报告（完整清单只在 `SKILL.md`，不在本文件重复）。
> 最后更新：<期号>（每次归档覆盖这一行；落后于 archive/ 最新期即为过期）
> 人物画像不进索引：每次启动从最近一份 report（当前区 `report.md`，无则 `archive/` 内最新 `*-report.md`）的「人生主题」「当前人物画像」现读。

## 一、主线卡

### 早起 / 作息 [活跃]（用户命名"早起"；别名"规律"待确认）
- 当前态：W12 把跑步焊进早上；W14 加班后断了一周；W15 用"前一晚收拾好"接回来。
- 时间线：
  - W12 六点半起床跑步，连续 10 天
  - W14 项目加班，链条断了
  - W15 "前一晚收拾好"降低启动成本，接回 4 天
- 未决：
  - 出差那几天早起怎么办
  - 断链之后接回来的最短路径是什么

### 清单 / 拖延 [常温]
- 当前态：W12 待办清单一长就开始拖；W14 发现"每天只挑三件"能启动。
- 时间线：
  - W12 清单越长越不动
  - W14 只挑三件，完成率明显上来
- 未决：
  - "三件"是按重要挑，还是按想做挑

### 存钱 / 记账 [静默]
- 当前态：W12 记了两周账，之后就断了，没再提过。
- 时间线：
  - W12 每天记一笔，坚持 14 天
- 未决：
  - 记账是为了看清什么，还是为了控制感

## 二、反复浮现的词 / 矛盾 / 价值（同机制归一组，不归并）

- **做完 / 完美**（×3，用户认领）：W12 "做完比做好重要"；W14 因为怕做不好而不开始；W15 "先写烂的第一版"。
- **硬模块**（×2，AI 提炼｜可推翻）：W12 跑步="要么 5 公里，要么不算"；W15 写作="要么写完一章，要么不写"。
- 疑似同簇｜待确认：`自律` ↔ `想自己说了算`（字面不同，未擅自合并，等用户认领）

> 合并规则：只有 ① 用户自己用了同一个词，或 ② 用户明确认领"这是同一个东西"，才合并。语义近但字面不同，标"疑似同簇｜待确认"，把归并权递回去。

## 三、主题总表

| 期号 | 本期主题（用户原词） | 人生主题一句话 | 报告 |
|---|---|---|---|
| 2026-W13 | 体检 / 早睡 / 周末加班 | 身体先亮红灯，计划才往后排。 | 有 |
| 2026-W14 | 加班 / 断链 / 项目收尾 | 事情一多，最先停的是照顾自己的那部分。 | 有 |
| 2026-W15 | 三件事 / 重新开始 / 出差 | 不是靠意志顶住，是把开始的门槛挪低。 | 有 |

> 「人生主题一句话」：有 report 的期从 report「人生主题」节截取原句/用户原话，不二次压缩；无 report 的期才允许 AI 自拟并标「（AI 提炼｜可推翻）」。
> 同一期多份快照：只占一行；本期主题取各快照方向词并集（去重）；人生主题取该期最后一份 report；时间线按快照顺序追加并注明「第 2 次 / Part2」。

## 四、散点（低承诺，×n）

- W14：同事推荐的那本书，一直没翻开（×1）
- W15：出差前想整理一次衣柜（×1）
- 必问：他说"等忙完这阵"之后到底想做什么（W15 记，×1）

> 已结案不留在散点：标「已结案」并移入档案。没有归属卡的钩子记散点，前缀 `钩:`。

## 五、背景区（休眠主线，一行）

- 学英语 / 口语 [休眠，W13 后无更新；到期 W20]：他要的是"能开口"，不是考试分数；遗产=确认了动机来自使用场景。

## 六、档案（深归档，不进默认包）

- 换城市 [深归档]：全文卡见 记忆归档.md。
- 已结案：W12 搬家清单；W13 体检；W14 项目复盘。
```

**「最后更新」的写入者（四种，缺一不可）**：首期创建、每期归档（五步写入顺序第 ② 步）、重建索引（第 6 步）、回溯迁移。读到的**老索引没有这一行** → 按"过期"处理（当线索用、引用前回快照核）；**补这一行只发生在下次归档/重建/回溯时，启动不写文件**。

**旧文件迁移（早期版本生成的索引/归档）**：索引标题若还写着"开局只读这里的 `### 线名 [活跃]` 行"，那句已作废（现在读六区全文），**下次归档/重建/回溯时**手删掉并补「最后更新」——这两处是模板遗留，不算用户手写，允许 AI 改；其余内容仍只做增量 edit。启动只读不写。`记忆归档.md` 若写着"读完把整卡移回 `记忆索引.md`、删背景区那一行"，以第 6 节复活规则为准（先建新卡、只补空缺、冷卡不删），顺手把那句改掉。

**为什么是六区：** 合并了"活跃主线索引"与"主线卡"——卡不多时，卡标题本身就是索引；多了「反复浮现的词 / 矛盾 / 价值」——remeet-me 特有，报告「纵向变化」的主粮；「主题总表」加「人生主题一句话」——直接喂报告。

## 4. 主线卡的写法

```markdown
### <线名> [活跃|常温|静默]（<用户命名 | AI 提炼｜可推翻>；别名：<待确认>）
- 当前态：1–2 句。开局承接"上次谈到哪了"靠它。
- **时间线**：每期一行，期号开头（`W41 …`）；≤8 行；最老的可压缩成段。
- 未决：≤5 条；每条是一个可追问的钩子，不是待办清单。
```

**线名的三种来源，优先级从高到低：**

1. 用户自己命名的词（"自律""清单""每天三件事"）——直接用。
2. 用户认领过的 AI 归纳（"这是同一个东西"）——用，标"用户认领"。
3. AI 从跨期材料里提炼的——用，但标 `AI 提炼｜可推翻`，且只在脑内当透镜，不主动向用户宣布。

**别名机制**：字面不同、语义相近的线（"自律" vs "想自己说了算"）不要合并；在卡上加 `别名：待确认`，等用户在访谈里认领。把归并权递回去。

**稀疏初始化**：新卡可以只有 2–3 行时间线、未决为空。不要为了填满四段而编。

**卡片文字只给 AI 看。** 要说给用户听的那一句，必须回快照取他自己的原话（或 report 里的原话引用）；不得把卡片的概括当作"你当时说"转述。概括里有判断的，一律带 `AI 提炼｜可推翻`，并用"我注意到…"递回，不用"你就是这样"。

## 5. 生命周期与档位（活跃 / 常温 / 静默 / 休眠）

**档位是算出来的，不是手标的。** n = **主题总表里、晚于该卡最后更新期号的已归档期数**（数期，不按自然周相减；表压缩成 8 期/年一行时，那一行按其覆盖的期号范围**展开**计期）。"卡最后更新期号"取卡内时间线里出现过的、不晚于最近归档期的最大期号；晚于它的（未来计划，如 `W52/53`）不计入。

> 两个坑：① 不能用"本周"——访谈开始时本周还没归档，每张卡都 n≥1，`[活跃]` 会永远是空的；② 不能按自然周相减——断了 3 周再回来，会一次掉 3 档。数"表里有几期晚于它"，才是真正的"几期没更新"。

**标记每次重算并覆盖。** 标题里的 `[活跃]` / `[常温]` / `[静默]` 是算出来的结果，不是手填的状态；归档定档后直接改写标题，旧标记只当线索。

| 档位 | n | 进入条件 |
|---|---|---|
| `[活跃]` | 0 | 最近一期有实质更新 |
| `[常温]` | 1–2 | 活跃 1 期没更新 |
| `[静默]` | 3 | 常温再 2 期没更新（累计 3） |
| 休眠（移出主线） | ≥4 | 静默再 1 期没更新（累计 4） |

任何一档被实质聊到 → 时间线 +1、当前态更新、**回到 `[活跃]`（n 归零）**。"提及但没展开"不算更新。

### 到期拉回（覆盖降档）

未决可以带一个到期期号：`- <钩子>（到期 2026-W51）`。用户说"10 周后""年底""下周"时换算成 `YYYY-Wnn` 记上。

**边界不清的时间不要猜**："本月 / 最近 / 过一阵 / 等忙完"这类落不到具体周的，写 `（到期待定：<原话>）`——它不是日期，**不参与到期扫描**。下一次访谈开场逐条问清（一次一条），问到周就换成 `（到期 YYYY-Wnn）`；用户说不清就保留待定，别自造一个日期。

归档时（写本期卡之前）扫一遍全部未决：

- **到期期号 ≤ 本期期号（含逾期）→ 这张卡强制回到 `[活跃]`**，不再等 n。开场轮转把它排在 `[活跃]` 最前面；逾期才说明"这条本来该在 X 月问"。
- 卡已经休眠 → 走复活：**直接取该线最近一张冷卡重建 `[活跃]` 卡**（不受"以本期材料先建"限制——到期不是新材料），把到期钩子放最前。
- **休眠时必须把到期日带到背景区**：卡内未决若带 `（到期 …）`，休眠时把最近的到期期号写进背景区行尾 `[休眠，W45；到期 W51]`——否则卡一休眠、未决离开索引，到期扫描就再也看不到它。
- 到期钩子问完：解决了 → 移入时间线；没解决 → 要么改一个新到期期号，要么去掉到期标记、降回普通未决（不再豁免）。

```
散点（提及未投入）
  ├─ 复提 → ×n（孵化观察，仍在散点层）
  ├─ 本期有实际投入/明确推进 → 进入本期主题
  └─ >3 期（第 4 期起）未复提：×1 → 剔除（偶发观察，弃之）；×n≥2 → 压成一行 `期号范围：<原词>（×n）` 留着；标了「必问」的永不按年龄剔除

本期主题（0–5 个）
  └─ 连续 ≥2 期、其中至少一期含实质讨论 → 聚合为主线卡（稀疏四段）

反复浮现的词（同一机制）
  ├─ 连续 ≥2 期指向同一机制（用户认领/同词）→ 归一组
  └─ 足够大且持续 → 可独立成线，或并入已有主线

[活跃] n=0
  ├─ 每期有内容 → 时间线 +1，n 归零
  └─ 1 期没更新 → [常温]
[常温] n=1–2
  └─ 再 2 期没更新（累计 3）→ [静默]
[静默] n=3
  └─ 再 1 期没更新（累计 4）→ 休眠：全文卡封存 记忆归档.md，背景区留一行

休眠主线
  ├─ 被重新提及 + 有实质推进 → 复活：**以本期材料先建出 `[活跃]` 卡**，再取该线**最近一张**冷卡补充（缺的未决补进来、旧语境压一行并入时间线）；冷卡**不删**，在其标题下追加 `（已于 <期号> 复活；以下为复活前快照，当前态以主线卡为准）`
  ├─ 仅提及无推进 → 用后即弃，不复活
  └─ 休眠 10 期无复活 → 深归档：档案一行，全文卡保留 记忆归档.md
```

**判定口径（照抄，勿自创）：** 方向性 = 本期有实际投入或明确推进计划；事项性 = 提及但未投入。**实质讨论** = 产生观点、决定、未决或推进动作的讨论。只满足"同一话题出现两次"不算，至少一期要有实质讨论。

**计数单位：** 档位 n、休眠/深归档的「期」= 主题总表的**期号**，不是行数、也不是快照数；主题总表压缩成「8 期一行」后，那一行按其覆盖的期号范围计期（`W35–W42` 算 8 期）。同一周多次访谈只算一期。

### 分区上限

| 区 | 上限 | 超限动作 |
|---|---|---|
| 单张主线卡时间线 | ≤ 8 行 | 最老 2–3 行压缩为 1 行（保留期号范围 + 弧线） |
| 单张主线卡未决 | ≤ 5 条 | 失效 → 档案；仍相关 → 并入时间线待办行 |
| 反复浮现的词 | ≤ 15 组；每组证据 ≤ 8 条 | 最久未复现 → 档案一行（词 + 最后一次语境）；组内超 8 条时把最老 3–4 条压成一行 `Wxx~Wyy：…`（保留原词与期号范围） |
| 主题总表 | 近 12 期逐行（第 13 期起压缩） | 更早压缩为 8 期一行（约一个季度；期号范围 + 主题迁移一句话）；再多就并成「年一行」 |
| 散点 | ≤ 15 条 | 按年龄下线：**×1 直接剔除**（偶发观察，不搬运；原文仍在 archive，检索可捞回）；**×n≥2 压成一行** `期号范围：<原词>（×n）`，不整行删；标「**必问：**」的永不按年龄剔除；了结的标「已结案」→ 档案。若 15 条全是「必问：」，**不静默删**：把最老的一条拎出来问一句"这条还留着吗"，用户说不要再删 |
| 背景区 | ≤ 20 行 | 最久 → 深归档（档案一行） |
| 档案 | ≤ 20 行 | 最老两条并成一行（线名范围 + 最后一次语境）；深层内容留在 `记忆归档.md` |

**没有全局字数上限，也没有主线卡张数上限。** 线上数量由档位自然控制（4 期不更新就休眠），体积由上面这张分区表控制。若卡片总数超过 12 张，归档时**只提示、不阻塞**：说一句"这些线里有没有可以先收起来的"，用户不答就继续归档，不追问、不自动休眠。

**GC 铁律：剔除 ≠ 删除（主线卡 / 未决 / 反复浮现的词）**——下线只是从常驻索引移开，原文与 `记忆归档.md` 仍在，可检索拉回。**散点另论**：它是偶发观察，×1 超龄直接弃（原文仍在 archive，只是不再常驻）；×n≥2 压行保留；标「必问：」的不按年龄下线。

**组内证据只增不删，超了压不删。** 一组反复浮现的词里那几条期号+原话是它存在的全部理由；超过 8 条时把最老 3–4 条压成一行（保留原词与期号范围），不能删掉证据却保留计数。要把一组减到零，只能整组下沉档案（那时计数同步重算）。

## 6. 归档五步（只在用户选"归档"时执行）

原则：**访谈材料零额外读取**（刚结束，全在上下文里）；唯一例外是休眠主线复活，要读 `记忆归档.md` 对应一张卡（约 300–500 token）。

1. **写/整理快照**
   - **先确认三件套已 `mv` 进 `archive/` 并按确认的名字改名**（`mv` 动作属 `archive-continuity.md` 的归档；本步只负责确认与命名）。期号取自改名后的文件名；第 5 步不重复这一步。
   - 快照 = 当前 `progress.md` + `question-log.md` + `report.md`（有则）。
   - 期号 = 快照文件名开头的 `YYYY-Wnn`（正则 `^(20\d{2}-W\d{2})`）。文件名没带周号时，按「基本信息」里的创建/最后更新日期换算成 ISO 周。同一周的所有快照合并为同一期。期号只在索引内部用（`question-log.md` 这类后台记录同理）；说给用户听用月份说法（"十月那次""九月第二周"），**不说 `W42`、不用 `P07` 之类序号**。
   - 快照「基本信息」保留；**有索引时**不再往新 `progress.md` 里抄「历史背景」；**无索引时**保留旧做法（有索引但不新鲜 → 仍读索引当线索 + 回快照核一句）。
   - 同一期多份快照：主题总表只一行；本期主题取各快照方向词并集；人生主题取该期最后一份 report；时间线按顺序追加，注明「第 2 次 / Part 2」。

2. **提取本期主题，匹配主线**
   - 从 `已探索的主题` / `阶段主线` / report「人生主题」里提 0–5 个**用户原词**。
   - 命中已有卡（`[活跃]` / `[常温]` / `[静默]`）→ 时间线 +1 行（期号开头），更新当前态，档位回到 `[活跃]`。
   - 命中背景区休眠主线 → 仅提及 → 用后即弃；有实质推进 → **复活（以当前为主）**：① 先按**本期材料**建出这张活跃卡（当前态 / 本期时间线 / 本期未决，只写本期内容）——休眠线此刻在索引里没有活跃卡，别去“取回整卡”；② 再读 `记忆归档.md` 中该线**最近一张**冷卡（休眠期号最大的那张），只把它有、新卡没有的东西补进来：缺的未决（总量仍受 ≤5）、该线旧语境压成一行并入时间线；冷卡内容**不进当前态**；③ 删背景区行；冷卡**不删、内容不改**，只在其标题下加一行 `（已于 <期号> 复活；以下为复活前快照，当前态以主线卡为准）`——这是「`记忆归档.md` 只追加」的例外（另一处是改旧说明）。带「已于…复活」标记的冷卡不再参与复活读取，只在检索时当历史文本用。若 `记忆归档.md` 里还留着旧说明（"读完把整卡移回 `记忆索引.md`、删背景区那一行"），以本节为准，顺手改掉那一句。

3. **更新主题总表 + 聚合检查**
   - 顺带比对 `archive/` 的文件名（带主题名），把先前缺的期一并补行，补不齐就在行尾标 `（待核）`。
   - 写入本期行：期号 / 本期主题 / 人生主题一句话 / 有无报告。
   - 聚合检查：同一方向连续 ≥2 期、且至少一期含实质讨论 → 建主线卡；同一机制连续 ≥2 期 → 建/更新一组反复浮现的词。
   - 建卡后，该方向后续由第 2 步常规维护，不再重复触发聚合。

4. **散点 + 未决维护**
   - 本期新钩子先按方向找卡 → 有卡就入卡内未决（每卡 ≤5）→ **确认无卡才**进散点（前缀 `钩:`）；同一内容不得同时出现在卡时间线和散点。
   - 散点维护：复提 → ×n；超龄（>3 期且未复提）：×1 **直接剔除**（偶发观察，原文仍在 archive）、×n≥2 压成一行留着；用户当场说过"这个以后要问我"的，行首加「**必问：**」，**永不按年龄剔除**（有卡后移入该卡未决）；了结的标「已结案」→ 档案；孵化成本期主题的从散点抽出。
   - 扫本期全文（在上下文里）：登记新未决钩子（每卡 ≤5）；带时间的钩子能落到周就写 `（到期 YYYY-Wnn）`、落不到就写 `（到期待定：<原话>）`，不猜；已解决的未决 → 移入时间线一行；已失效的 → 档案。
   - **未决不是待办清单**：只记"还能往下问的钩子"，不记"用户说他要做的事"。

5. **档位检查 + 分区上限**
   - 到期扫描：**卡内未决与背景区行尾**的 `（到期 YYYY-Wnn）` 里，凡 ≤ 本期 → 该卡强制 `[活跃]`（已休眠的先按 §5 复活），开场排最前。
   - 按 §5 的 n 值给每张卡定档（0 活跃 / 1–2 常温 / 3 静默）；n≥4 → 休眠：全文卡写入 `记忆归档.md`，卡片标题写 `### <线名>（休眠于 <期号>）`（同一线二次休眠另起一张，不覆盖旧的），背景区留一行（线名 + 停更期 + 遗产一句话；有到期钩子时行尾加 `；到期 Wnn`）。
   - 背景区休眠 10 期以上 → 深归档：档案一行，全文卡保留。
   - 把超过分区上限的区压回上限；某卡最末行超过 **12 个月**时，归档时同样休眠（写「长期未更新」）——这条按日历算，与是否周更无关；不催、不提示用户。
   - **写入顺序（防丢用户手改）**：① 快照已在第 1 步进 `archive/`（不在这里 `mv`）；② **read 现有 `记忆索引.md`，在原文上做增量 `edit`**（只改本期涉及的区块 + 文件头「最后更新」行），**不做全量重生成**；③ `记忆归档.md` 只追加。只有"重建索引"才允许全量生成，且必须先把旧文件备份为 `记忆索引.bak-YYYYMMDD.md`。

## 7. 启动组装公式

```
启动 =
  SKILL.md（常驻规则，已在上下文）
  + 记忆索引.md 六区全文（`档案` 只用于定位，不引用其内容）
  + [续接] 当前 progress.md 全文（必须）
  + [新周期] 最近一份 report（当前区 `report.md`，无则 `archive/` 内最新 `*-report.md`；再没有就读最近 progress 的提炼块；沉淀.html 可作语气补充）
  + [按需] 用户点名 / 检索命中的快照片段
  + [无索引] 回退旧轻读：grep 每份 progress 的「反复浮现的词」+ report 的「人生主题/画像」
```

**启动顺序不能乱：**

1. 先扫当前区有没有 `progress.md`（残留提醒优先——它可能还没进索引）。
2. 列一次 `archive/` 的文件名前缀，与主题总表的行逐行比对，按"**有没有这一行**"判差集——期号是唯一键（一行一期），不比主题名。「最后更新」只用来判断**索引是否新鲜**（落后于最新期 → 给用户一句提示），**不参与差集定义**：
   - 有差集 → **启动只提示、不补写**：说一句"有一期还没进索引，下次归档我补上"，然后照常访谈；补齐发生在下次归档（五步第 3 步会重跑本步），或用户当场要求时。以 `长跨度-*` 命名的整体报告不算一期，不参与差集比对。
   - 真的要用到缺期内容时才读：只用该期 report/沉淀的提炼块（不整份读），引用时明说"这条我手上不全，你记得那次…"。**启动不写 `（待核）`**——标记留到下次归档（五步第 3 步）或重建/迁移时补。
   - `（待核）` **写法固定**：行级写在行尾；卡级写在卡标题行尾（`### <线名> [活跃]（待核）`）；整份索引级别的写在文件头「最后更新」行尾。标了的行/卡一律当线索不当事实；每次归档重跑本步，能补就补、补上就删标记，补不上就留着（不要为了"看起来干净"删掉它）。
3. 有索引（哪怕过期）→ 读索引全文；无索引但有 archive → 旧轻读。索引状态**不影响**残留/解档/全新分流。
4. 再听用户开场，不从索引里主动汇报任何东西。

## 8. 检索规则（search-as-tool）

**唯一来源是 `SKILL.md` 的「检索规则」，本节不再维护副本。** 那份规则在访谈中随时要用，所以常驻在 `SKILL.md`；两处并存必然漂移（改一处忘一处，执行时就成了二选一）。要改检索规则，只改 `SKILL.md`，改完回来看这条指针是否仍成立。

本文件只补一条索引侧的边界：**索引的 `档案` 区与 `记忆归档.md` 只用于定位期号和读取冷卡，不作引语来源**——说给用户听的每句话，仍要回该期 progress/report 取原话；取不到就照实说"只找到整理稿/旧卡，原话我手上没有"。

## 9. 报告联动

`references/output-report.md` 的「纵向变化」优先从索引取：

- 主题迁移：排主题总表的「人生主题一句话」；这一列必须有 report 的期从 report 原句截取，无 report 的期才允许 AI 自拟并标「（AI 提炼｜可推翻）」。
- 原词跨周期归组：直接用「反复浮现的词」，每条带语境 + 出现期号 + 认领状态；组名是 AI 提炼的，标 `AI 提炼｜可推翻`。
- 定向模块演变：用主线卡的时间线。
- 索引没有的，再定向读快照；不要重新全量读。
- 报告里不出现"主线卡 / 散点 / 休眠 / GC / 索引"这些词。

## 10. 失败恢复与重建

| 故障 | 处置 |
|---|---|
| 归档时索引写失败 | 快照已进 `archive/`，安全；**下次归档**按第 7 节的期号比对补写；补不动就在文件头「最后更新」行尾标 `（待核）` 并提议另开一次会话重建（启动只提示、不补写） |
| `记忆归档.md` 写失败 | 休眠卡暂时留在索引（允许短时超限），下次重试；绝不因此丢卡 |
| 索引被误删/想重来 | 从 `archive/` 重建；若旧文件还在，重建前先备份 |
| 索引与快照冲突 | 以快照 + 用户当场确认为准；索引标 `（待核）`；不擅自改快照 |
| 用户手动改了索引 | 以用户为准；AI 不覆盖用户手改的那一行/那一段，除非用户让改 |
| 用户改了/重命名了快照 | 期号以文件名现值为准；主题总表按新前缀改行；内容冲突以快照为准，索引标 `（待核）` |
| 用户删除/移走快照 | 该期相关行与卡内该期行从索引下线；索引不得比 `archive/` 活得更久 |
| 索引过期（「最后更新」落后于 `archive/` 最新期） | 仍读索引当线索，引用前回快照核一句；缺期**在下次归档**按第 7 节补（启动只提示不补写）；不因此停用索引 |

**重建索引（低频，单独一次会话做，不要塞进访谈）：**

1. 列 `archive/` 全部快照，按期号排序。
2. 逐期提取：期号 / 本期主题（0–5，用户原词）/ 人生主题一句话（report 优先）/ open loops 中可跨期的钩子 / 反复浮现的词 / 关键事件。
3. 建卡：同一方向连续 ≥2 期 → 主线卡；同一机制连续 ≥2 期 → 一组反复浮现的词；其余进主题总表/散点。
4. 应用当前档位：按 §5 的 n 值定档，n≥4 → 休眠，全文卡写 `记忆归档.md`，背景区一行。
5. 应用分区上限；校验：每张卡 ≥2 期证据、每期在总表有行、各分区不超上限。
6. 写 `记忆索引.md`（含文件头 `最后更新：<archive/ 中最新的期号>`）+ `记忆归档.md`；若旧索引还在，先备份；**不改 `archive/` 任何文件**。

## 11. 一次性回溯迁移 → 见 `references/migration.md`

首次建索引、把旧 archive 补进索引、大规模重建时读那一份：范围、来源优先级（含 `*-沉淀.html` 节标题带空格的坑）、分批节奏、验证清单 12 条都在里面。**日常归档不读它。**

## 12. 反模式与红线

- 把索引内容念给用户听。
- 用"主线卡/散点/休眠/GC"跟用户说话。
- 为了填满 0–5 个主题词而造词。
- 把语义相近的词强行合并（"自律"="想自己说了算"）。
- 把"用户说他要做的事"记成未决钩子。
- 归档时重读所有快照（访谈材料零额外读取；休眠复活读记忆归档是唯一例外）。
- 把卡片的概括当作"你当时说"转述给用户。
- 照抄各期自记的 ×n 序数（冲突时以逐期记录为准，总数重算）。
- 改 `archive/` 里的任何文件（AI 不改；用户自改是允许的）。
- 分区超上限还继续追加。
- 开局用"上次你说要跟进 X，进展如何"审问式开场。
- 用未决钩子开场时评价用户"没大事/白过了/浪费了"，或把范围确认 + 钩子 + 追问一次全抛。
- 用户选"丢弃/继续"时还去更新索引。
