# 归档与快照（收口/归档/解档时读）

> 本文件由 SKILL.md 按需加载：只在用户说出结束语义、走到归档确认时读。平时不进上下文。

### 归档：会话快照（结束时问一句）

**🔴 CHECKPOINT（移动/清空文件前必停）：归档不是自动的。** 用户说出结束语义、收口流程走到最后时，问一句（三选）：

> 「这段要**归档**吗？我按「十月下旬那段」存一份快照，名字想改直接说。也可以**丢弃**不留，或者你说继续那我们就接着聊。」

**选「继续」= 撤销刚才的结束语义**：回到提问循环接着问，不再问归档，直到用户重新说出结束语义。归档三选只在这一刻出现一次，不重复问。

**说人话，不报文件名**：快照文件名可以带期号（`2026-W43-主题`），但**期号/路径只进文件名，不出口**。对用户只说月份或事由（"十月下旬那段""上周那次"），不说 `2026-W43`、不说 `archive/`、不说"索引/工作区"。归档完只告知去向（"存好了，下次说接着聊"）+ 下次可接的内容。

- **归档**：把当前 `progress.md` + `question-log.md` + `report.md`（有则）移进 `archive/`，改名 = `YYYY-Wnn-主题[-Part2]`（期号取快照所在 ISO 周；主题取自 `progress.md`「基本信息」的「访谈主题」；该格为空或只是占位（如"待浮现"）时，用本期最突出的一两个用户原词，轻度清洗：去掉 `-` 与非法字符）。**三件套全部到位才算归档完成**，不是 `progress.md` 移走就算完（判据见下方「写盘回执与幂等」）。**当前区清空只清三件套**——`记忆索引.md` / `记忆归档.md` 不动。**随后执行 `references/memory-index.md` 的「归档五步」**（第 1 步负责 `mv` 与改名）：首期创建 `记忆索引.md`，此后每期增量更新；选「丢弃/继续」时不碰索引。
- **丢弃**（体验派）：**删除当前区三件套工作文件**（`progress.md` / `question-log.md` / `report.md`），不进 archive，不留历史——从"只做一次"到"常做"自然覆盖，**不需要任何模式开关**。`记忆索引.md` / `记忆归档.md` 不动。删不干净，下次开场还会触发残留提醒。

**索引更新（只在选「归档」时）**：先 `mv` 快照进 `archive/`，再 **read 现有 `记忆索引.md`，只做增量 `edit`**（本期卡、主题总表新行、散点、反复浮现的词），**不整体重写**；`记忆归档.md` 只追加。只有「重建索引」才全量生成，且先备份 `记忆索引.bak-YYYYMMDD.md`。索引写失败不影响快照；**下次归档**时按 memory-index.md 第 7 节的期号比对补期或重建（启动只提示、不补写）。**写完把文件头「最后更新」改为本期期号**，并按 memory-index.md §5 的分区上限核一遍（哪些区超了、超了怎么压，全在那一节）。

### 写盘回执与幂等（归档 / 索引 / 冷卡 / 报告都适用）

每次动文件前先认一下这张表的「成功判据」；失败时先判**效果状态**，再决定要不要重试。**部分成功只补缺，未知效果先查证。**

| 操作 | 成功判据（全部满足才算完成） | 部分成功怎么办 | 幂等键（重跑前先查） |
|---|---|---|---|
| 归档 `mv` 三件套 | `archive/` 里有本期 `progress.md` + `question-log.md`（+ 有则 `report.md`），且当前区三件套都不在 | **只补缺的那几件**；已移走的**绝不**移回、不重跑整步。对用户说"快照已存好，还差 X 没移，下次补" | `YYYY-Wnn-主题`：目标名已存在且内容一致 → 跳过；不一致 → 不覆盖，按 `-Part2` 另存并告诉用户 |
| 索引增量 `edit` | 本期行已写入 + 文件头「最后更新」= 本期期号 + 改到的区块都在 | 只补没写上的区块；补不动就在对应行/卡/文件头标 `（待核）`，说"索引下次归档补"，**不重跑 `mv`** | `期号 + 区块`：先读现有索引确认本期行是否已存在；存在就只补缺，不整段重写 |
| `记忆归档.md` 追加冷卡 | 该线该休眠期号的卡只有一份；标题与「当前态 / 时间线 / 未决 / 休眠原因」都在 | 不重复追加；缺字段只补缺字段，不覆盖旧卡 | `线名 + 休眠期号`：追加前先 `grep` 标题，已存在就跳过 |
| `report.md` 写入 | 文件存在 + 七节骨架齐全（无历史的「纵向变化」可跳过）+ 用户点过头 | 保留当前区旧 `report.md`（若有），下次重试；**不因为报告写失败就归档** | `阶段范围 + 生成时间`：重写前确认是否已有同范围报告，避免覆盖 |

**效果状态口径**：`none` 没动 → 可以重试；`applied` 全动完 → 不重试；`partial` 动了一部分 → 只补缺、不重跑；`unknown` 报错了但不知道动没动 → **先查文件再决定**，不自动重试。写失败时对用户只说人话："我先确认一下刚才那步有没有成功，再决定要不要重来。"

**禁止**：把 `partial` 当完成；把 `unknown` 当失败直接重跑；用 `mv` 把已进 `archive/` 的文件移回当前区。

**期号**：**一个自然周就是一个期**，期号 = 快照所在周的 `YYYY-Wnn`（ISO 周，周一为一周之始）。同一周的所有快照——续传、`-Part2`、同一周多次独立访谈——合并为同一期，主题总表只占一行；跨周的快照各自成期。**没有事件式期号，也没有 `YYYY-MM` 期号。**「最近 / 排序」按该周周一的日期，不按字符串。休眠/深归档按**期号**计数，不按快照数。

**手动修改（简版）**：归档确认时可直接改名；归档后就是普通 markdown，用户想改直接编辑（告知路径），或一句话指令（如"把上份快照打开，我还想补"→ 按「解档续传」处理）。**不**做合并/拆分/批量管理这类重系统。索引也是普通 Markdown：用户改过的以用户为准，AI 只做增量 edit、不整体重写，避免抹掉手改。
