# 归档与快照（收口/归档/解档时读）

> 本文件由 SKILL.md 按需加载：只在用户说出结束语义、走到归档确认时读。平时不进上下文。

### 归档：会话快照（结束时问一句）

**🔴 CHECKPOINT（移动/清空文件前必停）：归档不是自动的。** 用户说出结束语义、收口流程走到最后时，问一句（三选）：

> 「这段要**归档**吗？我按「十月下旬那段」记一份，名字想改直接说。也可以**丢弃**不留，或者你说继续那我们就接着聊。」

**选「继续」= 撤销刚才的结束语义**：回到提问循环接着问，不再问归档，直到用户重新说出结束语义。归档三选只在这一刻出现一次，不重复问。

**说人话，不报文件名**：快照文件名可以带期号（`2026-W43-主题`），但**期号/路径只进文件名，不出口**。对用户只说月份或事由（"十月下旬那段""上周那次"），不说 `2026-W43`、不说 `archive/`、不说"索引/工作区"。归档完只告知去向（"存好了，下次说接着聊"）+ 下次可接的内容。

- **归档**：把当前 `progress.md` + `question-log.md`（本场关闭提问日志则缺该件不算缺）+ `report.md`（有则且属于本期、已过七节判据）移进 `archive/`，改名 = `YYYY-Wnn-主题[-Part2]`（再冲突顺延 `-Part3`…；期号取快照所在 ISO 周；主题取自 `progress.md`「基本信息」的「访谈主题」；该格为空或只是占位（如"待浮现"）时，用本期最突出的一两个用户原词，轻度清洗：去掉 `-` 与非法字符）。**该有的都到位才算归档完成（`report.md` 有且属于本期、已过七节判据才算；没写就不算缺）**，不是 `progress.md` 移走就算完（判据见下方「写盘回执与幂等」）。**当前区清空只清三件套（`report.md` 有则）**——`记忆索引.md` / `记忆归档.md` 不动。**随后执行 `references/memory-index.md` 的「归档五步」**（第 1 步负责 `mv` 与改名）：首期创建 `记忆索引.md`，此后每期增量更新；选「丢弃/继续」时不碰索引。
- **丢弃**（体验派）：**删除当前区三件套工作文件与临时件**（`progress.md` / `question-log.md` / `report.md` / `report.md.tmp` / `report.md.bak-*`），不进 archive，不留历史——从"只做一次"到"常做"自然覆盖，**不需要任何模式开关**。`记忆索引.md` / `记忆归档.md` 不动。删不干净，下次开场还会触发残留提醒。

**索引更新（只在选「归档」时）**：先 `mv` 快照进 `archive/`，再 **read 现有 `记忆索引.md`，只做增量 `edit`**（本期卡、主题总表新行、散点、反复浮现的词），**不整体重写**；`记忆归档.md` 只追加。只有「重建索引」才全量生成，且先备份 `记忆索引.bak-YYYYMMDD.md`。索引写失败不影响快照；**下次归档**时按 memory-index.md 第 7 节的期号比对补期或重建（启动只提示、不补写）。**写完把文件头「最后更新」改为本期期号**，并按 memory-index.md §5 的分区上限核一遍（哪些区超了、超了怎么压，全在那一节）。

### 写盘回执与幂等（归档 / 索引 / 冷卡 / 报告都适用）

每次做这四类写操作前先认一下这张表的「成功判据」；失败时先判**效果状态**，再决定要不要重试。**部分成功只补缺，未知效果先查证。**

| 操作 | 成功判据（全部满足才算完成） | 部分成功怎么办 | 幂等键（重跑前先查） |
|---|---|---|---|
| 归档 `mv` | `archive/` 里有本期 `progress.md` + `question-log.md`（提问日志本场关闭时缺该件不算缺）+（有则且属于本期、已通过七节判据的 `report.md`），且当前区该有的都不在；临时件按下方原子落盘段处置（不完整 `.tmp` / `.bak-*` 删净，完整待合并 `.tmp` 除外） | **只补缺的那几件**；已移走的**绝不**移回、不重跑整步。**目标已就位 = 该有的每个文件在 `archive/` 都有同名对应件且逐项内容一致；缺任何一件 → 没就位，只补缺，不得删当前区残留；若「缺件 + 已有对应件内容不一致」→ 先停手问用户，不补移任何文件（对用户说"上次那段的记录我这儿有两份、对不上——你更想留哪一份，还是两份都留着？"）。只有当前文件自己的对应件存在且内容一致时，才可删该当前副本。** `-Part2/-Part3` 只用于内容确实不同的另一份快照（目标完整且任一件不同 → 整套另存），不用于没移完的补缺。对用户说"这段已经存好了，还差一样没搬，下次补" | `YYYY-Wnn-主题`：**逐文件**判定；该有的每个文件都有同名对应且内容一致才算已归档；缺件 → 只补缺；内容不同的另一份才按 `-Part2` 另存（`-Part2` 也占用则顺延 `-Part3`）并告诉用户又存了一份（不覆盖旧的） |
| 索引增量 `edit` | 索引启用时：本期行已写入或已合并 + 文件头「最后更新」= 本期期号 + 改到的区块都在（区块 = 归档五步第 2–5 步触到的卡 / 主题总表 / 散点 / 反复浮现的词 + 文件头）；索引关闭则跳过本行 | 只补没写上的区块；补不动就在对应行/卡/文件头标 `（待核）`，说"这次记录存好了，剩下我下次补"，**不重跑 `mv`** | `期号 + 区块`：先读现有索引确认本期行是否已存在；**存在 → 合并本期新快照**（方向词并集、时间线追加、人生主题取本期最后一份 report，不新增行），**不是整行跳过**；不存在 → 新增一行 |
| `记忆归档.md` 追加冷卡 | 该线该休眠期号的卡只有一份；标题 + 当前态 + 时间线 + 休眠原因都在（未决可为空） | 不重复追加；缺字段只补缺字段，不覆盖旧卡 | `线名 + 休眠期号`：追加前先 `grep` 标题，已存在就跳过 |
| `report.md` 写入 | `report.md` 有则：属于本期（「阶段背景」覆盖本次回顾范围）+ 文件存在 + 七节骨架齐全（无历史的「纵向变化」可跳过）+ 用户点过头 + 已通过 `report.md.tmp → mv` 落盘（半份 `.tmp` 不算） | **tmp 写入/自检失败 → 删不完整 `.tmp`，旧 `report.md` 不动**；**tmp 完整但 `mv` 失败 → 保留 `.tmp`，旧 `report.md` 不动，下次只重试 `mv`、不重写**；**报告写失败本身不触发归档，也不阻止用户已选择的归档**：用户要归档就照常归档其余文件，如实说"这次报告没存上，下次补" | `阶段范围 + 报告类型`（阶段报告 / 长跨度报告）：重写前确认是否已有同范围同类型报告，避免覆盖；用户明确要求重写时才覆盖。生成时间只作元数据，不作键 |

**长跨度报告**另存为 `archive/长跨度-<范围>-report.md`，不覆盖当前区 `report.md`；成功判据另加这一条。**丢弃**用 `rm -f`，判据 = 当前区该有的和 `report.md.tmp` / `report.md.bak-*` 都不在；可安全重跑。

**`report.md` 原子落盘**：先写 `report.md.tmp` → 七节自检 → `mv -f report.md.tmp report.md`。**tmp 写入/自检失败 → 删不完整 `.tmp`，旧 `report.md` 不动**；**tmp 完整但 `mv` 失败 → 保留 `.tmp`，旧 `report.md` 不动，下次只重试 `mv`、不重写**。`.tmp` / `.bak` 不归档、不进索引；启动时忽略 `.tmp`，但若 `report.md.tmp` 完整且 `report.md` 缺失，提示可重试合并，不直接删。**归档完成后的临时件**：`.bak-*` 和不完整 `.tmp` 一并删掉；`report.md` 尚缺且 `.tmp` 完整时保留待合并（见上句），不因归档完成而删；它们不算快照内容。 归档时 `report.md` 只有属于本期（由本次会话生成、阶段背景覆盖本次回顾范围）且通过七节判据才算"有"；半份/旧阶段/本轮要求重写但失败的旧 report 不算，不自动归档；旧阶段或待重写的 report 留在当前区，不作为可补移残留，只提示是否另存。

**顺序 gate**：归档 `mv` 补齐后才做索引完成判定；`mv` 仍 partial 就在文件头/本期行标 `（待核：记录未齐）`，不把索引写成已完成。

**效果状态口径**：`none` 没动 → 可以重试；`applied` 全动完 → 不重试；`partial` 动了一部分 → 只补缺、不重跑；`unknown` 报错了但不知道动没动 → **先查文件再决定**：`archive/` 与当前区都在时用 `cmp -s`（或 SHA-256）**逐文件**比对，该文件自己的对应件一致才清该副本；缺对应件 → 不删；不一致 → 两份都留、问用户；**不自动重试**。写失败时对用户只说人话："我先确认一下刚才那步有没有成功，再决定要不要重来。"

**禁止**：把 `partial` 当完成；把 `unknown` 当失败直接重跑；用 `mv` 把已进 `archive/` 的文件移回当前区；对用户说"快照 / 索引 / archive / 期号 / 文件名"这类后台词。

**期号**：**一个自然周就是一个期**，期号 = 快照所在周的 `YYYY-Wnn`（ISO 周，周一为一周之始）。同一周的所有快照——续传、`-Part2`、同一周多次独立访谈——合并为同一期，主题总表只占一行；跨周的快照各自成期。**没有事件式期号，也没有 `YYYY-MM` 期号。**「最近 / 排序」按该周周一的日期，不按字符串。休眠/深归档按**期号**计数，不按快照数。

**手动修改（简版）**：归档确认时可直接改名；归档后就是普通 markdown，用户想改直接编辑（告知路径），或一句话指令（如"把上次那份打开，我还想补"→ 按「解档续传」处理）。**不**做合并/拆分/批量管理这类重系统。索引也是普通 Markdown：用户改过的以用户为准，AI 只做增量 edit、不整体重写，避免抹掉手改。
