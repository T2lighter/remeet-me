# 一次性回溯迁移（首次建索引 / 把旧快照补进索引时读）——9 期实操验证

> 本文件由 SKILL.md 按需加载：只在首次建索引、旧 archive 回溯迁移、或大规模重建时读。日常归档不读——那时只需要 `memory-index.md`。

## 1. 范围

`archive/*-progress.md`、`archive/*-report.md`、`archive/*-沉淀.html`。不纳入 `*-question-log.md`、样式/脚本。**所有快照都落到它所属的自然周（`YYYY-Wnn`），不分事件式期号。**

**回溯不在本次访谈里做**：单独开一次会话，或明确告诉用户"这次只补历史、不聊新的"。

## 2. 来源优先级

1. `*-沉淀.html`：每期都有「主线串联 / 关键词（他自己起的名字）/ 要点（带走的话）」，是回溯的最佳入口；但它只用于定位期号/主题与找回原词，不作一手引语来源。**注意：这些节标题在文件里带空格**（`主 线 串 联` / `关 键 词` / `要 点`），按字面搜 `要点` 会 0 命中——用 `grep 'class="part"'` 或 `主 *线 *串 *联` 这种写法。
2. `*-report.md`：「人生主题」「当前人物画像」「纵向变化」，有报告的期用它交叉核对；无报告的期只走沉淀 + progress。
3. `*-progress.md`：只在沉淀/报告缺信息时，读「阶段主线 / 已探索的主题 / open loops / 反复浮现的词 / 关键事件库」；不整份读。
4. 旧「历史背景」节是二手摘要，只用来定位，不作为一手证据。

## 3. 分批

按 2–3 期一批，先写"期级提取卡"（期号 / 本期主题 / 人生主题一句话 / 原词 / 未决 / 散点），再合并成索引。不要一次读全部全文；按节 grep/sed 取。

## 4. 验证清单（迁移与重建共用）

1. 主题总表全覆盖：每期（每个 `YYYY-Wnn`）各出现一次，期号与文件名前缀一致，不得漏；同周多次独立访谈与 `-Part2` 合并为同一期。
2. 卡有证据：每张活跃主线至少 2 期证据；单期内容只进主题总表/散点，不建卡。
3. 时间线可追溯：随机抽 2–3 行，回快照能找到出处。
4. 归并纪律：没有"语义近就合并"；`自律` vs `意志力`、`生存焦虑` vs `生存危机` 这类必须标"待确认"。
5. 休眠判定：最后 4 期无更新 → 休眠；重点检查长期只在背景区出现、且再未被提起的线。
6. 上限：活跃 ≤8、时间线 ≤8、未决 ≤5、反复浮现的词 ≤15 组、散点 ≤15、主题总表近 12 期、索引典型≤2.5K token（≈3,200 字）/ 硬≤4K token（≈5,200 字）。
7. 系统词零泄漏：索引里可以有系统词；用户可见的报告/对话里没有。
8. archive 未变：回溯前后 `git status` / mtime / 校验和一致（只算 AI 的操作；用户自己改的不在此列）。
9. 可重建：删掉索引后能按同样流程重建；若旧文件还在，重建前先备份；重建会丢失用户手改，所以"可重建"不是"无损"。
10. 序数不照抄：各期自记的 ×n 经常不一致；索引只记"哪几期出现过"，总数重算，冲突处标"计数待核"。
11. 用户复核：用户亲自读一遍索引，重点改三处——线名、别名归并、未决钩子是否真的是"还想问的"。
12. 写盘齐全：`记忆索引.md` 已写，且文件头 `最后更新：<最新期号>` 与 `archive/` 最新期一致；`记忆归档.md` 已写。
